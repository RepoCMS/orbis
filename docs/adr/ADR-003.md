# ADR-003: ULID as Primary Identifier

**Status:** Accepted  
**Date:** 2026-08-06  
**Deciders:** Architecture Team

## Context

The system requires globally unique identifiers that:
- Are sortable by creation time (for pagination, ordering)
- Have no collision risk across distributed systems
- Are URL-safe and human-readable
- Work well with database indexes

## Decision

Use **ULID (Universally Unique Lexicographically Sortable Identifier)** as the primary identifier for all domain entities.

### Implementation

- Custom Value Object for each ID type: `UserIdValueObject`, `RoleIdValueObject`, `ProductIdValueObject`, etc.
- All IDs wrap a ULID string (26 characters, Crockford base32)
- Custom DBAL types for Doctrine persistence: `UserIdType`, `RoleIdType`, etc.
- Factory methods use `Ulid::generate()` from `ulid/ulid` package

### Value Object Pattern

```php
final readonly class UserIdValueObject
{
    public function __construct(
        private string $id // 26-char ULID string
    ) {
        self::validate($id);
    }
    
    public static function generate(): self {
        return new self(Ulid::generate()->toString());
    }
}
```

## Consequences

### Positive
- Time-sortable IDs enable efficient pagination and ordering
- No coordination needed for ID generation across services
- Compact (26 chars) and URL-safe
- Monotonic ordering improves database index performance

### Negative
- Slightly larger than UUID (16 bytes vs 16 bytes binary, but 26 vs 36 chars string)
- Requires custom DBAL types for Doctrine
- Need to validate ULID format on input

### Neutral
- All entities follow consistent ID pattern
- Value objects provide type safety across BC boundaries
