# ADR-005: Doctrine ORM for Persistence

**Status:** Accepted  
**Date:** 2026-08-06  
**Deciders:** Architecture Team

## Context

The project needs a robust ORM for PHP that supports:
- Custom value object mapping
- Soft delete patterns
- Complex repository queries
- Database migrations
- Cross-BC read access (via shared kernel interfaces)

## Decision

Use **Doctrine ORM** as the persistence layer with XML mapping files.

### Configuration

```yaml
# config/packages/doctrine.yaml
doctrine:
    dbal:
        driver: pdo_mysql
        server_version: '8.0'
        charset: utf8mb4
    orm:
        auto_generate_proxy_classes: true
        naming_strategy: doctrine.orm.naming_strategy.underscore_number_aware
        auto_mapping: true
        mappings:
            Identity:
                is_bundle: false
                type: xml
                dir: '%kernel.project_dir%/src/app/Identity/Infrastructure/Persistence/Doctrine/Mapping'
                prefix: 'App\Identity\Domain\Entities'
```

### Mapping Pattern

All entity mappings use XML files (not annotations or attributes) for:
- Clear separation of concerns
- No PHP execution during mapping definition
- Easy review and diff in Git

### Soft Delete Implementation

```xml
<!-- User.orm.xml -->
<entity name="App\Identity\Domain\Entities\User" table="identity_users">
    <field name="deletedAt" column="deleted_at" type="datetime_immutable" nullable="true" />
    <!-- ... -->
</entity>
```

Repository queries filter by `deleted_at IS NULL` by default.

## Consequences

### Positive
- Mature ecosystem with extensive tooling
- XML mappings are version-controllable and reviewable
- Powerful query builder and DQL
- Excellent migration tooling via Doctrine Migrations

### Negative
- XML mapping files add verbosity
- Doctrine proxy classes can cause issues in some scenarios
- Learning curve for complex mappings

### Neutral
- Well-suited for the PHP/Symfony ecosystem
- Large community and documentation
